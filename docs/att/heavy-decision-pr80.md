# Heavy decision — PR #80 ATT-1 IMAP transport

**Status:** owner decision. Docs only. No code, no live IMAP, no install.
**As-of:** 2026-09-28
**Inputs:** Heavy reply 2026-09-28 ~02:15 PT (Q1–Q14); `docs/att/imap-transport-heavy-brief-pr80.md`; `docs/att/imap-transport-options-pr80.md`; PR #80 head `1d1e4fed64ef5eaec9797157b12a195d82d26f37` (parent `87397f7a`).
**PII:** none. Keychain item names are not written here. The placeholder is `<keychain-item>`.

The owner accepts Heavy's ATT-1-only exception to `docs/ops-terminal.md` §"IMAP live checks via curl imaps (never Python sockets)". `imaplib` may fetch ATT-1 part bytes and nothing else. ATT-0 stays on pinned `/usr/bin/curl`. There is no curl `-X` fallback. A live dial is not part of landing the client.

Why this exception, and not a deferral: curl `-X` cannot return a FETCH `{n}` literal intact, and that is fundamental on the builds already measured. Native URL-form returned exact bytes on curl 8.5.0 loopback and cannot send `EXAMINE` plus `BODY.PEEK`; it `SELECT`s and sends `BODY[]`, which is the read-write class already holding PR #88. `--output` and `--trace-ascii` do not recover the literal, and a trace records the login secret. Loopback `imaplib` is the only option that kept the bytes and stayed read-only. The Errno 9 failure mode is why the standing rule exists. It is handled by failing closed (`FetchRefuse`, store nothing, no second client), not by pretending the live host was retested. Loopback success does not clear a live dial. That dial is an operator card below.

## ADOPT — planned implementation PRs

Each PR is one concern. Tests are offline or loopback on `127.0.0.1` only. The suite is `PYTHONPATH=tests python3 -m unittest discover -s tests`.

1. **Q1.** Against `main`. Loopback proof that `/usr/bin/curl` custom-request (`-X`) UID FETCH does not return a multi-line literal intact, including a line equal to the live tag. No production client change. Test: `tests/test_curl_x_literal_fundamental.py`.
2. **Q3.** Against `main`. Loopback transcript: native `imaps://` URL-form sends `SELECT` and `BODY[]` / `BODY[section]<offset.length>`, not `EXAMINE` and not `BODY.PEEK`, and a prior `EXAMINE` does not stick. Test: `tests/test_curl_urlform_not_readonly.py`.
3. **Q4.** Against `main`. Loopback proof that `--output` and `--trace-ascii` on a custom-request FETCH see the truncated read, and that the trace contains the fixture login secret. Static guard: production curl argv rejects `--trace` / `--trace-ascii`. Test: `tests/test_curl_trace_output_not_literal.py`.
4. **Q5.** Stacked on PR #80 (`cursor/att-fetch-extract-cf9c`, head `1d1e4fed`). Library only: overall transfer deadline, R4 (empty or NIL at offset 0 is an error; a later empty body is a clean end; NIL must be the FETCH item, not bytes that look like NIL), `ssl.create_default_context` with `SSLKEYLOGFILE` cleared unless `MAILROOM_SSLKEYLOGFILE_ALLOW=1`, password only from the callback and never logged, `OSError` errno 9 mapped to `FetchRefuse` with nothing stored, no curl fallback helper. Test: `tests/test_att1_imaplib_safeguards.py`. The production client stays curl until Q6.
5. **Q6.** Stacked on the Q5 branch (itself on PR #80). `ImapPartClient` uses that library as the only transport. No curl `-X` fallback. Written exception in `docs/att/att1-imaplib-exception.md` for this path alone. Loopback: binary, tag-like, no-CRLF, partial slices, `{0}`, NIL, empty-at-offset-0 refuse, transcript is `EXAMINE` + `BODY.PEEK` and not `SELECT` / `STORE` / `EXPUNGE`. Test: `tests/test_att1_imaplib_transport.py`.
6. **Q9.** Against `main`. The socket guard allowlist is empty or exactly `scripts/attachments/imaplib_part.py`. A second allowlisted path fails. `scripts/attachments/meta_fill.py` does not import `imaplib`. Test: extend `tests/test_repo_no_python_imap_sockets.py`.
7. **Q10.** Against `main`. `docs/att/att1-ci-pin.md`: ATT-1 CI pins the Python version and `ssl.OPENSSL_VERSION` of the interpreter that runs the suite, and does not require Mini curl 8.7.1. URL-form on 8.5.0 is not Mini proof. Test: `tests/test_att1_ci_pin.py`.
8. **Q12.** Against `main`. Metadata-fill CLI exit 4 and stderr `error: imap auth failed` for an auth/keychain open failure. Other `curl_failures` stay exit 0. Status 2 unchanged. Tests pin the new status and the new stderr line.
9. **Q13.** Against `main`. `scripts/imap_keychain.py` timeout and fill exit 5. Tests pin the timeout, the kill, the status, and the stderr line `error: imap keychain read timed out`.
10. **Q14.** Against `main`. Daily wrapper and `scripts/imap_keychain.py` read the item from the environment or the gitignored config file, drop the legacy fallback, hard-stop on a miss, and apply the 15s timeout on the wrapper's `security` call. Tests use `<keychain-item>` or a fixture name that is not a deployed item. No deployed item name in any file this PR adds or changes.

Q5 and Q6 are the #80 transport. They do not merge from this work. Q6 does not ship without the Q5 safeguards, which it stacks on.

## Proposed operator cards

These are descriptions only. This change set does not run them.

1. **ATT-1 live check (before any live run of Q6).** One host (the machine that will run the job). One small read-only `BODY.PEEK` partial of one part. Byte-compare to a known fixture. Confirm the transcript is `EXAMINE` and `BODY.PEEK`, not `SELECT`, `STORE`, or `EXPUNGE`, and that flags on that message did not change. If the dial fails (including Errno 9), stop. Do not fall back to curl `-X`. Do not retry on another client. Record `/usr/bin/curl --version` in that log only; it does not gate the `imaplib` client.
2. **Mini vs repo daily drift (Q8).** Read-only diff of the Mini daily shell and `mailroom_daily.py` against the repo copies. Do not copy either direction until that diff is reviewed. Promote Mini bytes only if Mini is the intended running chain. Otherwise reinstall the repo copy onto Mini. No install in this card's first step; the diff is the whole card.
3. **First catch-up caps (Q11).** Before the first daily after the gap, set a per-run cap and an age limit for urgent texts and for bill reminders, and a cap for a tombstone pass that is larger than local `present_on_server`. No `EXPUNGE`. Numbers are not chosen here.
4. **Search window marker (Q7).** Design, outside ATT-1 and outside `scripts/ask_mail.py`, a window marker that pauses search writes to `ask_audit` and drafts and never takes `write.lock`. Do not design the sidecar database in that card. Search must not become a `write.lock` holder.
